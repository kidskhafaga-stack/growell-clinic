# How to interpret a GAHAR standard

The handbook states that a standard consists of:

1. **Standard Statement**
2. **Keywords**
3. **Intent**
4. **Survey Process Guide**
5. **Evidence of Compliance (EOCs)**
6. **Related Standards**

## Standard Statement

Each standard is preceded by a code and states the required level of quality or achievement.

## Keywords

Keywords identify the most important elements of the standard and help answer:

> What is the standard intended to measure?

## Intent

The intent explains the full meaning of the standard.

It normally contains:

- **Normative intent** — why the standard is required.
- **Informative intent** — how the organization can interpret and implement it.

When a standard specifies minimum process components, these components are essential parts of compliance.

## Evidence of Compliance (EOCs)

EOCs identify what surveyors review and score during the on-site survey.

Full compliance is evaluated in relation to the applicable **Met EOCs**.

## Survey Process Guide

The survey process guide assists surveyors in assessing and rating the required EOCs.

## Related Standards

Related standards must be considered because healthcare processes are interconnected and a single standard usually measures only one part of a larger care process.

# Terminology

The handbook distinguishes between:

- Process
- Documented Process
- Policy
- Procedure
- Plan
- Guideline
- Clinical care program
- Protocol
- Document
- Record
- Physician
- Medical Staff Member

### Process

A series of actions or steps taken to achieve a particular end.

### Documented Process

A documented description of a process. It may take the form of a:

- Policy
- Procedure
- Program
- Plan
- Guideline
- Protocol

### Document vs Record

- **Document:** created by planning what needs to be done.
- **Record:** created when something is done.

# Proposed software compliance mapping

For the medical system, each GAHAR requirement should be mapped using this structure:

| Field | Description |
|---|---|
| GAHAR Chapter | Chapter code/name |
| Standard Code | Exact GAHAR standard code |
| Standard Statement | Exact requirement |
| EOC | Evidence of compliance |
| System Module | Relevant software module |
| Feature | Specific implementation |
| Evidence | Report/log/document produced by system |
| Status | Met / Partial / Gap / N/A |
| Gap | Missing functionality |
| Action | Required implementation |
| Owner | Responsible team |
| Priority | Critical / High / Medium / Low |

## Example

```text
GAHAR Standard
    ↓
EOC
    ↓
Required organizational process
    ↓
System feature
    ↓
Audit trail / report / record
    ↓
Survey evidence
```

This prevents the software from merely claiming compliance without producing verifiable evidence.

---

# Core principle for implementation

The system should not invent clinical or accreditation requirements.

Every compliance claim should be traceable to:

1. The official GAHAR standard.
2. The exact EOC where applicable.
3. The implemented system behavior.
4. A reproducible record, report, audit trail, or document proving implementation.
